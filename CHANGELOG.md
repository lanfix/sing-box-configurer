# Changelog

## v0.9.0

- Карта трафика на странице «Обзор» (Vue Flow): inbound-ы → правила маршрутизации по порядку → группы → urltest-ы → outbound-ы по рабочему конфигу sing-box. Карту можно двигать, масштабировать и перетаскивать узлы (расположение запоминается), подписки с тремя и больше серверами свернуты в один узел, есть миникарта и слой DNS (у каждого DNS-сервера видно, через какой outbound уходят запросы; сервер без detour работает напрямую — связь с direct пунктиром). Из боковой панели можно переключить узел selector-а и замерить задержку urltest-а.
- Живой режим: соединения Clash API привязываются к связям карты — толщина связи и подпись показывают скорость, по клику на узел, связь или строку правил видно, какие хосты через них идут.
- Поиск пути по домену или IP: какое правило сработает, какое правило группы (ручное или из URL-источника) совпало, какой DNS-сервер резолвит домен и в какой outbound уйдет соединение. API `/api/topology`, `/api/topology/connections`, `/api/topology/trace`.

## v0.8.0

- Страница «Управление» разделена: прокси-группы Clash API — отдельный пункт «Прокси», настройки sing-box и плановая перезагрузка — «Система → Настройки», обновления — «Система → Обновление». Старый адрес `/control` ведет на настройки.
- Пользовательские DNS-правила и дополнительные поля секции dns — на одной странице «DNS → Расширенные» с общим сохранением (API `/api/dns/advanced` вместо `/api/dns/rules`; `/api/dns/settings` больше не меняет дополнительные поля). Поля, которые задает конфигуратор (`servers`, `rules`, `final`, `strategy`, `cache_capacity`, `optimistic`, `timeout`), в дополнительных полях запрещены и при рендере игнорируются: раньше они молча перезаписывали системные правила.
- Локально собранный образ (`docker compose build`): вместо ошибки «is not a Docker Hub image» страница обновления объясняет, что обновление выполняется пересборкой, и показывает последний релиз для справки. Запуск обновления для такого образа отклоняется с понятной причиной.
- Amnezia: если версию sing-box узнать не удалось (не запущен или недоступен Clash API), больше не пишется, что sing-box не поддерживает AmneziaWG, — серверы AmneziaWG в этом случае и так попадают в конфиг.
- Переработаны формы: поля с подсказками и пометкой «необязательно», переключатели вместо флажков, длительности числом с единицей, списки IP и origin-ов чипами, проверка значений до отправки, ошибки сервера — прямо в форме.
- Форма DNS-сервера: протокол карточками, популярные серверы в один клик, вставка адреса ссылкой целиком, редкие параметры свернуты. Подсказывает, если для IP-адреса не указано имя из сертификата.
- Настройки DNS и системы сохраняются одной кнопкой с отметкой о несохраненных изменениях; уход со страницы без сохранения требует подтверждения.
- Добавление и редактирование групп, DNS-серверов и записей, источников URL — в модальных окнах; действия в таблицах — иконками. Системный `confirm()` заменен собственным диалогом, уведомления показываются в углу экрана.

## v0.7.0

- Раздел Outbounds разделен на «Серверы» и «URLTest».
- Свои urltest-ы: состав собирается при каждом рендере из источников (все outbound-ы, добавленные вручную, подписка Happ или Amnezia целиком либо отдельный профиль), regexp-фильтра по тегу, явно добавленных и исключенных вручную или regexp-ом outbound-ов. Состав виден в форме до сохранения. selector-ы и urltest-ы (в том числе балансировщики подписок Happ) по источникам не подбираются — их можно добавить явно.
- urltest `auto` больше не встроенный: он хранится в app.json и его можно изменить или удалить. Существующие инсталляции получают `auto` из всех outbound-ов, как раньше.
- urltest без outbound-ов в конфиг не попадает: группы, выбравшие его, получают block, а не direct (раньше пустой `auto` вел напрямую).
- urltest, выбранный outbound-ом группы или detour-ом DNS-сервера, удалить нельзя.
- Новая инсталляция создает группу default (outbound `auto`, DNS-сервер `cloudflare`) вместо direct.

## v0.6.2

- Плановая перезагрузка sing-box выполняется конфигуратором. Расписание (cron) и часовой пояс настраиваются на странице «Управление», по умолчанию — ежедневно в 06:00 UTC, как в cron-scheduler. Видны время следующей и результат последней перезагрузки.
- После обновления удалите сервис cron-scheduler из `docker-compose.yaml` и выполните `docker compose up -d --remove-orphans`.

## v0.6.1

- Share-ссылки vless и trojan: параметры транспорта (ws, grpc, httpupgrade, http) записываются на одном уровне с type, как ждет sing-box. Транспорт xhttp отклоняется: sing-box его не поддерживает.
- Share-ссылки hysteria2: диапазон портов записывается через двоеточие (`20000:29999`).
- Миграция исправляет outbound-ы, уже добавленные из таких ссылок (вложенный транспорт и диапазоны портов).
- Точки в меню «Подписки»: желтая — подписка Happ или Amnezia Premium заканчивается меньше чем через неделю либо израсходовано 75% трафика, красная — меньше 3 дней, подписка истекла или израсходовано 90% трафика.

## v0.6.0

- Точка правды — app.json: конфиг sing-box рендерится из групп, правил, DNS, outbound-ов, inbound-ов, подписок и вшитого базового шаблона. Редактор конфига и временный конфиг убраны.
- Страница «Конфиг» показывает итоговый конфиг и diff с рабочим. Применение проверяет конфиг командой `sing-box check` (через exec docker-controller), сохраняет бэкап, атомарно заменяет рабочий конфиг и перезапускает sing-box; если он не запустился, прежний конфиг восстанавливается.
- Новый интерфейс на Vue 3: меню с группами (Правила, DNS, Подписки), страницы загружаются по требованию.
- DNS: серверы UDP/TCP/DoT/DoH/DoH3/DoQ/local/DHCP, общие параметры и пользовательские DNS-правила настраиваются в интерфейсе.
- Outbound-ы, добавленные вручную, хранятся в app.json и редактируются как JSON. Встроенный urltest `auto` включает все outbound-ы, кроме selector-ов. Серверы подписок Happ и Amnezia попадают в конфиг сразу, без синхронизации.
- Mixed-прокси настраиваются на странице Inbounds. tun-in и dns-in встроены.
- Системные группы block (соединения отклоняются правилом `reject`) и bypass (мимо туннеля, заменяет флаг «Мимо туннеля»). Группу default можно удалить, если она пустая. Новая инсталляция создает группу direct.
- Общие настройки на странице «Управление»: уровень логов, токен Clash API и CORS-origin-ы.
- Адрес rule-set-ов задается в `rule_set_base_url` (по умолчанию порт `listen_addr`), каталог бэкапов — в `backup_dir`.
- Миграция переносит в app.json DNS-серверы, пользовательские DNS-правила, ручные outbound-ы, mixed-inbound-ы и настройки из текущего конфига sing-box.
- Требуется docker-controller v0.0.3. Рекомендуется монтировать каталоги data и sing-box вместо отдельных файлов (см. README).

## v0.5.1

- Эндпоинты rule-set-ов отдают ETag и отвечают 304, если набор не изменился. Раньше sing-box каждые 30 секунд заново загружал все наборы и неатомарно пересоздавал nftables-набор `route_exclude_address_set` (все адреса исключений удалялись и добавлялись заново), из-за чего отваливался nftables monitor sing-box.

## v0.5.0

- Раздел «DNS-записи»: домены и IP-адреса, которыми отвечает DNS sing-box. Записи попадают в hosts-сервер `configurer-hosts` и первое правило `dns.rules`, синхронизируются в конфиг через diff.
- Миграция переносит пользовательские hosts-серверы с `predefined` (например, `static-hosts`) в DNS-записи.
- DNS-правила групп больше не содержат `evaluate`/`respond`: через DNS-сервер группы резолвятся только домены из ее правил, остальное сразу идет в `dns.final` без запроса через VPN. Правила `evaluate`/`respond` из v0.4.0 удаляются при синхронизации групп. Домены сервисов, заданных только IP-адресами (например, `youtube.com` при списке CIDR YouTube), нужно добавить в правила группы.

## v0.4.0

- Rule-set группы разделен на домены (`configurer-<группа>`) и IP/CIDR (`configurer-<группа>@ip`): доменный набор в DNS-правилах больше не включает legacy address filter, и через DNS-сервер группы идут запросы любого типа.
- У группы появился DNS-сервер. Конфигуратор прописывает DNS-правила группы: домены — на ее сервер, IP-адреса — через `evaluate`/`match_response`.
- Пока DNS-правила есть хотя бы у одной группы, HTTPS-записи в DNS не отдаются: без ECH sniff видит настоящий домен, и сайты за Cloudflare снова идут по правилам групп (TCP и QUIC).
- Эндпоинты rule-set-ов отвечают 503, пока URL источники набора не загружены после старта: sing-box не получает неполный набор.
- Миграция переносит DNS-серверы групп из ручных DNS-правил `{"rule_set": "configurer-<группа>", "server": ...}`. Новые rule-set-ы и DNS-правила появятся после синхронизации групп.

## v0.3.0

- Флаг «Мимо туннеля» у правил и URL источников: трафик по ним sing-box не перехватывает.
- IP и CIDR исключений отсекаются в nftables через `route_exclude_address_set`, домены — правилом `bypass` в pre-match.
- Миграция добавляет в конфиг sing-box rule-set `configurer-bypass`; изменения вступят в силу после перезапуска sing-box.
- Имя группы `bypass` зарезервировано.
