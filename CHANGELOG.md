# Changelog

## v0.15.0

- Новая страница «Устройства» — профиль устройства сети по MAC-адресу: **обход** (маршрутизация по группам), **без обхода** (весь трафик напрямую мимо правил групп, домены резолвит выбранный DNS-сервер) или **без интернета** (соединения и DNS-запросы отклоняются первым правилом). Устройствам без своего профиля действует профиль по умолчанию, но только в сетях LAN: адреса самого хоста и исключения (VPN-клиенты, серверы) под него не попадают. По умолчанию это обход, поэтому без настройки ничего не меняется.
- Конфигуратор раз в минуту читает таблицу соседей хоста и показывает найденные устройства: их можно добавить в один клик, а новые устройства без профиля отмечаются точкой у пункта меню. Сети LAN определяются по интерфейсам, где есть соседи (docker, туннели и VPN не учитываются), и дополняются вручную.
- sing-box сам узнает MAC-адрес источника (`route.find_neighbor`) и забирает списки у конфигуратора rule-set-ами `devices@direct` и `devices@blocked`, поэтому устройства и политика меняются без перезапуска sing-box. **После обновления примените конфиг**: rule-set-ы устройств попадут в рабочий конфиг.
- Нужен sing-box-lx 1.14.2-lx.11-mac.1 или новее — сборка [lanfix/sing-box-lx](https://github.com/lanfix/sing-box-lx) с MAC-адресами в rule-set. Updater теперь обновляет sing-box вместе с конфигуратором: если установлен sing-box-lx старше нужного, новый образ (docker) или архив релиза с проверкой по `SHA256SUMS` (systemd) загружается заранее, а sing-box заменяется после проверки новой версии конфигуратора; в docker новый тег прописывается в `docker-compose.yaml`. Если новый sing-box не проработал 10 секунд, возвращается прежний, а обновление конфигуратора не откатывается. Свой образ, официальный sing-box и более новые версии не трогаются.
- Поддержка MAC-адресов проверяется командой `sing-box check` с пробным конфигом: при запуске, при смене версии sing-box и раз в минуту, пока Clash API недоступен. Без подтвержденной поддержки профили не рендерятся, а rule-set-ы устройств пустые: sing-box без поддержки отверг бы набор с MAC-адресами и не запустился. Если sing-box заменили старым бинарником, его запрос rule-set-а перепроверяет поддержку, и sing-box запускается с пустым набором.
- «Соединения»: у источника — имя и MAC-адрес устройства, поиск по ним. Карта трафика подписывает правила устройств, «Поиск пути» показывает путь для устройства с обходом.
- Скрипты установки ставят sing-box-lx `v1.14.2-lx.11-mac.1` из [lanfix/sing-box-lx](https://github.com/lanfix/sing-box-lx); репозиторий релизов sing-box в `install-systemd.sh` задается переменной `SING_BOX_REPO`.
- Типовая схема подключения (сервер — шлюз и DNS локальной сети) — в `docs/typical-use.md`.

## v0.14.0

- Автоматическая проверка обновлений на странице «Система → Обновление»: конфигуратор сам проверяет новые версии каждый час, 3, 6, 12 часов или раз в сутки, даже если панель не открыта. О новой версии он пишет в свой журнал, а в открытой панели у пункта «Система» появляется точка без перезагрузки страницы. После неудачной проверки повтор — через 10 минут. Обновление само не устанавливается. По умолчанию проверка выключена.
- Раньше обновления проверялись только при загрузке страницы панели, и в долго открытой вкладке новая версия не появлялась.

## v0.13.2

- Группа block теперь срабатывает раньше bypass. Раньше адрес, попавший в обе группы (например, из URL-источника bypass), уходил мимо туннеля и не блокировался: IP и домены bypass исключаются из tun еще в nftables, а правило bypass стояло раньше `reject`. Теперь подсети block вычитаются из IP-набора bypass, домены и суффиксы bypass, целиком покрытые block, из набора убираются, домены block не резолвятся (DNS-правило `predefined` с `NXDOMAIN` первым в `dns.rules`), а `reject` по IP группы block стоит перед правилом bypass. **После обновления примените конфиг.**
- Предупреждения о перекрытии URL-источниками и «Поиск пути» учитывают новый порядок: block, bypass, затем группы в порядке создания.

## v0.13.0

- Интерфейс работает на телефонах и планшетах. До 1024 px меню скрыто за кнопкой в шапке и выдвигается поверх страницы (закрывается крестиком, тапом мимо, Esc или переходом на страницу); точка на кнопке показывает, что в меню есть пункт, требующий внимания.
- На телефоне (до 720 px): строка с заголовком закреплена сверху, а кнопки страницы идут под ней и уезжают при прокрутке. Таблицы превращаются в карточки: заголовок и кнопки действий сверху, бейджи в строку, остальные поля с подписями. Окна выезжают снизу на всю ширину, кнопки «Отмена» и «Сохранить» закреплены внизу окна. Фильтры над таблицами, формы, плитки «Обзора» и страницы настроек перестроены под узкий экран.
- Поля ввода на телефоне — 16 px: iOS больше не увеличивает страницу при фокусе. На сенсорных экранах крупнее кнопки и переключатели, окна не открывают клавиатуру сами, подсказка графика скорости показывается по касанию.
- Карта трафика на телефоне не сжимается до нечитаемого масштаба: видно начало карты, остальное листается пальцем. Миникарта скрыта, сведения об узле выезжают снизу.
- Учитываются вырез и закругления экрана (safe area) и видимая высота без адресной строки браузера (`dvh`).
- При переходе на другую страницу прокрутка начинается сверху (раньше сохранялась с предыдущей страницы).

## v0.12.0

- Новая страница «Соединения»: активные соединения sing-box с хостом, устройством-источником, группой, цепочкой outbound-ов, скоростью, трафиком и длительностью. Поиск, фильтры по группе, outbound-у и сети, сортировка, пауза обновления. Соединения закрываются по одному, найденные фильтром или все — приложения переподключатся уже по текущим правилам.
- Домен или IP соединения и результат «Поиска пути» на карте можно добавить в группу правил прямо оттуда: окно предлагает уровень домена (`www.youtube.com` → `youtube.com`), показывает пересечения до добавления и может сразу применить правила.
- Пересечения ручных правил запрещены во всех группах и для IP: адрес внутри существующей подсети, подсеть, включающая существующий адрес, и вложенные подсети отклоняются (для доменов это работало и раньше). Значения нормализуются: домены — в нижнем регистре без точки в конце и `*.` в начале, подсети — с обнуленными битами хоста (`10.1.2.3/8` → `10.0.0.0/8`). Форма «Одиночные» проверяет значения на лету и показывает пересечения еще до добавления.
- Пересечение ручного правила со значением URL-источника разрешено. Если группа источника стоит выше (bypass, block, затем группы в порядке создания), форма предупреждает, что для этого значения сработает источник.
- Новая страница «Система → Логи»: журналы sing-box и конфигуратора — логи контейнеров в docker и journald в systemd. Последние 200–5000 строк, автообновление, фильтр по уровню и тексту, копирование и скачивание.
- Новая страница «Система → Перенос данных»: выгрузка `app.json` одним файлом и загрузка из файла. Перед загрузкой видно содержимое файла. Файл прежней версии приводится миграциями к текущей схеме, файл более новой версии загрузить нельзя. Вход в панель и разрешенные доменные имена по умолчанию остаются текущими (переключатель «Заменить доступ к панели данными из файла»). Прежние данные сохраняются в `backups/app-<время>.json`, после загрузки конфигуратор перезапускается.
- «Конфиг → Резервные копии»: рабочий конфиг sing-box можно вернуть из одной из 10 последних копий — например, если новый конфиг сломал работу. Копия сравнивается с рабочим конфигом и применяется так же, как обычный конфиг (с проверкой и возвратом при неудачном запуске). Данные конфигуратора не меняются, поэтому после отката итоговый конфиг отличается от рабочего.
- Share-ссылки `ss://` (SIP002 с методом и паролем в base64 или как есть, плагины obfs-local и v2ray-plugin, старый формат целиком в base64) и `vmess://` (формат v2rayN и `uuid@host:port?…`). Имена профилей из ссылок раскодируются (`%F0%9F%87%A9%F0%9F%87%AA` → 🇩🇪) для всех протоколов.
- Тест скорости outbound-ов на странице «Outbounds → Серверы»: по одному или все показанные по очереди. Файл скачивается через outbound в несколько потоков, результат — скорость в Мбит/с, отклик и сервер загрузки. Тестовые серверы пробуются по списку: заблокированный в стране роутера или выхода сервер пропускается, если не ответил за 10 секунд. Список серверов, длительность и число потоков — в «Система → Настройки».
- Служебный inbound `configurer-sources` теперь рендерится всегда и пропускает в любой outbound, кроме block (раньше — только в outbound-ы загрузки источников): через него идет тест скорости. **После обновления примените конфиг**, иначе тест скорости попросит об этом. На карте трафика и в «Поиске пути» служебный inbound и его правила не показываются.

## v0.11.0

- Новый раздел «Система → Безопасность»: вход по логину и паролю (перенесен из «Настроек»), адрес панели и описание встроенной защиты от чужих сайтов.
- Защита от DNS rebinding: панель отвечает, только если ее открыли по IP-адресу, `localhost` или доменному имени из списка разрешенных (`*.example.com` — с поддоменами). Адреса из `rule_set_base_url` и `listen_addr` разрешены всегда. Сохранить список, без которого текущий адрес панели перестанет открываться, нельзя; выключить проверку из консоли — `sing-box-configurer security reset`. **Если вы открываете панель по домену (например, через reverse proxy), после обновления откройте ее по IP и добавьте домен в список.**
- Запросы со страниц других сайтов (включая соседние порты того же адреса) к API отклоняются при любом методе — чужая страница не может ни прочитать данные, ни изменить настройки (CSRF). Файлы интерфейса нельзя подключить на чужой странице (`Cross-Origin-Resource-Policy`), Content Security Policy разрешает интерфейсу только собственные скрипты. Переход на панель по ссылке с другого сайта работает.
- XSS: ссылки «Поддержка» и «Кабинет» профиля Happ приходят от сервера подписки и выводились без проверки — ссылка `javascript:` выполнила бы код в панели по клику. Теперь допускаются только `http` и `https` (и на сервере, и в интерфейсе), ранее сохраненные ссылки очищаются при запуске.
- Обновленные серверы подписок Happ сразу переносятся и в итоговый, и в работающий конфиг sing-box (настройка «Система → Настройки → Подписки Happ → Применять обновления сразу», по умолчанию включена). Переносятся только изменения серверов: другие неприменённые изменения остаются ждать применения. Профиль, который еще не применялся, не переносится. Если серверы изменились у нескольких профилей при фоновом обновлении, sing-box перезапускается один раз.
- Интервал обновления подписки Happ, который присылает сервер, ограничен: не чаще раза в 10 минут и не реже раза в 30 дней (слишком большое значение переполняло таймер, и подписка обновлялась каждые 5 минут).
- Установка одной командой для обоих вариантов: `install-docker.sh` (docker compose: при необходимости ставит Docker, создает `/opt/sing-box-configurer/docker-compose.yaml` с последним релизом, запускает контейнеры) и `install-systemd.sh` (прежний `install.sh`, переименован). Оба скрипта отключают DNS-заглушку systemd-resolved, если она занимает порт 53 (`KEEP_RESOLVED=1` — не трогать), ждут запуска конфигуратора и проверяют, что sing-box работает. Скрипт для docker принимает `ADMIN_USER`/`ADMIN_PASSWORD`, `PORT`, `INSTALL_DIR`, `VERSION`, `SING_BOX_VERSION`.
- Документация по установке вынесена в `docs/install-docker.md` и `docs/install-systemd.md`: параметры, требования, порт 53, файлы, обновление, восстановление доступа и удаление. README актуализирован.

## v0.10.3

- На карте трафика правила `reject` и outbound `block` теперь показаны одним узлом «Отклонить» (раньше узлов было два: «Отклонить» и `block`).
- Защита от CSRF: изменяющие запросы с других сайтов отклоняются (`http.CrossOriginProtection`). Раньше любая страница, открытая в браузере пользователя локальной сети, могла отправить POST в API: при выключенном входе — без ограничений, при включенном — с соседнего порта того же хоста. Добавлены заголовки против встраивания панели во фрейм (`X-Frame-Options`, `frame-ancestors`) и `nosniff`.
- У HTTP-сервера появились таймауты чтения заголовков и простаивающих соединений (защита от slowloris).
- Проверка входа учитывает и экранированный путь запроса, который сопоставляет `ServeMux`: `%2F` внутри сегмента не уводит проверку на путь вне `/api/`.
- `app.json` (хэш пароля, ключ подписи сессий, ключи прокси) записывается с правами 0600, права файлов от прежних версий ужесточаются при первой записи. `install.sh` передает пароль администратора через stdin, а не аргументом, видимым в списке процессов.
- Одиночный IPv6-адрес из URL-источника превращался в подсеть `/32` (например, `2001:db8::1/32` — вся сеть провайдера), теперь — `/128`. То же для адреса клиента Amnezia без маски.
- Правила `ip` и `cidr` проверяются при добавлении: неверное значение раньше попадало в rule-set, и sing-box не мог его загрузить.
- Массовое добавление правил выдавало ID вида «время-номер», которые совпадали у двух добавлений в одну секунду, — теперь UUID.
- URL-источники: ссылка должна быть http или https, интервал обновления — не больше года (больший переполнял таймер, и источник загружался без пауз). Список больше 64 МиБ отклоняется. Каждая загрузка оставляла открытое keep-alive-соединение — теперь оно закрывается. Источник, удаленный сразу после применения, больше не загружается в фоне бесконечно.
- Размер тела запросов переключения прокси и запуска обновления ограничен, как у остальных методов API.

## v0.10.1

- Загруженные списки источников URL сохраняются на диске (`url-sources` рядом с `app.json`): после перезапуска конфигуратор сразу отдает rule-set-ы, и sing-box запускается, даже если источники пока недоступны (раньше без DNS и VPN sing-box не мог стартовать, а источники — загрузиться).
- Источник, который не загрузился и которого нет в кэше, больше не держит всю группу в ответе 503: группа отдается без него. Неудачная загрузка повторяется через минуту с удвоением интервала, а не через час.
- Источник можно загружать через outbound или группу («Загружать через» в форме источника) — например, список с заблокированного сайта через VPN. Для этого в конфиг sing-box добавляется служебный mixed-inbound `configurer-sources` (порт 9091, доступ по паролю) с правилами `auth_user` → outbound. Кнопка «Проверить» тоже загружает список через выбранный outbound.
- В README — как менять `docker-compose.yaml`, не останавливая sing-box, и запасной DNS для сервера, который резолвит имена через sing-box.

## v0.10.0

- Вход в панель по логину и паролю: включается в «Система → Настройки → Доступ к панели», своя страница входа, сессия на 30 дней, кнопка выхода в меню, блокировка на 10 минут после 5 неверных попыток. Без входа доступны только `/api/health` и rule-set-ы для sing-box. Сброс из консоли — `sing-box-configurer auth reset`, задать логин и пароль — `auth set`.
- Установка без Docker: sing-box и конфигуратор службами systemd, установка одной командой (`install.sh`), обновление из интерфейса с проверкой и откатом, как в docker.
- Контейнер docker-controller больше не нужен: конфигуратор сам работает с Docker API через смонтированный `/var/run/docker.sock`. Управление sing-box и обновление вынесены в платформы установки (docker, systemd).
- При первом запуске конфигуратор сам записывает стартовый конфиг sing-box. Конфиг сервиса необязателен: значения по умолчанию подбираются под платформу, в docker Clash API по умолчанию — `http://host.docker.internal:9090`.
- Релизы собирает GitHub Actions: бинарники для linux/amd64, arm64 и armv7 публикуются в GitHub Releases, а docker-образ (теперь multi-arch, на Alpine) собирается из тех же бинарников.
- Прежние миграции данных удалены: поддерживаются данные версии v0.9.0 и новее.

## v0.5.0

- Раздел «DNS-записи»: домены и IP-адреса, которыми отвечает DNS sing-box. Записи попадают в hosts-сервер `configurer-hosts` и первое правило `dns.rules`, синхронизируются в конфиг через diff.

Домены сервисов, заданных только IP-адресами (например, `youtube.com` при списке CIDR YouTube), нужно добавить в правила группы.

## v0.4.0

- Rule-set группы разделен на домены (`configurer-<группа>`) и IP/CIDR (`configurer-<группа>@ip`): доменный набор в DNS-правилах больше не включает legacy address filter, и через DNS-сервер группы идут запросы любого типа.
- У группы появился DNS-сервер. Конфигуратор прописывает DNS-правила группы: домены — на ее сервер, IP-адреса — через `evaluate`/`match_response`.
- Пока DNS-правила есть хотя бы у одной группы, HTTPS-записи в DNS не отдаются: без ECH sniff видит настоящий домен, и сайты за Cloudflare снова идут по правилам групп (TCP и QUIC).
- Эндпоинты rule-set-ов отвечают 503, пока URL источники набора не загружены после старта: sing-box не получает неполный набор.
- Миграция переносит DNS-серверы групп из ручных DNS-правил `{"rule_set": "configurer-<группа>", "server": ...}`. Новые rule-set-ы и DNS-правила появятся после синхронизации групп.
