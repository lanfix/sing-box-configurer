# Sing-Box Конфигуратор

Веб-приложение на Go для управления правилами маршрутизации Sing-Box через HTTP API.

## Архитектура

Приложение предоставляет HTTP API эндпоинт `/api/ruleset`, который возвращает rule set в формате sing-box. Sing-box настраивается на получение rule set из этого эндпоинта, что позволяет динамически обновлять правила маршрутизации без перезагрузки sing-box и без генерации конфигурационных файлов.

### Преимущества архитектуры

- ✅ Не требуется перезагрузка sing-box при изменении правил
- ✅ Sing-box автоматически подхватывает изменения из HTTP источника
- ✅ Простое развертывание в контейнерах (конфигуратор + sing-box с host network)
- ✅ Нет необходимости в файлах конфигурации sing-box
- ✅ Централизованное управление правилами

## Возможности

- ✅ Управление правилами маршрутизации через веб-интерфейс
- ✅ Поддержка доменов, суффиксов доменов, IP адресов и CIDR
- ✅ **URL источники** - автоматическая загрузка списков правил из внешних URL
- ✅ Периодическое обновление URL источников с настраиваемым интервалом
- ✅ HTTP API для получения rule set в формате sing-box
- ✅ Раздельное управление правилами и их применение
- ✅ Визуальная индикация статуса правил (применено/ожидает)
- ✅ Валидация URL источников перед добавлением
- ✅ Мониторинг статуса загрузки URL источников (успех/ошибка)
- ✅ Гибкая конфигурация через config.json или флаги командной строки
- ✅ По умолчанию весь трафик идет напрямую, только указанные правила через VPN

## Требования

- Go 1.26+
- Sing-Box (может работать в отдельном контейнере)

## Установка

1. Склонируйте репозиторий:
```bash
git clone https://github.com/lanfix/sing-box-configurer.git
cd sing-box-configurer
```

2. Соберите приложение:
```bash
go build -o sing-box-configurer ./cmd
```

Статические файлы (HTML, CSS, JS) встроены в бинарник, поэтому для запуска не требуется папка `web/`.

3. Запустите приложение:
```bash
./sing-box-configurer
```

## Конфигурация

Приложение использует файл `config.json` для настройки. Пример:

```json
{
  "rules_path": "rules.json",
  "listen_addr": ":8080"
}
```

### Параметры конфигурации

- **rules_path** - путь к файлу с правилами (по умолчанию: `rules.json`)
- **listen_addr** - адрес для веб-интерфейса и API (по умолчанию: `:8080`)

### Флаги командной строки

Вы можете переопределить параметры конфигурации через флаги:

```bash
./sing-box-configurer -config /path/to/config.json
./sing-box-configurer -rules /path/to/rules.json
./sing-box-configurer -listen :9090
```

Флаги имеют приоритет над параметрами из config.json.

## Использование

### Настройка Sing-Box

Настройте sing-box для получения rule set из HTTP источника. В конфигурации sing-box добавьте:

```json
{
  "route": {
    "rule_set": [
      {
        "tag": "vpn-rules",
        "type": "remote",
        "format": "source",
        "url": "http://configurer-host:8080/api/ruleset",
        "download_detour": "direct",
        "update_interval": "1m"
      }
    ],
    "rules": [
      {
        "rule_set": ["vpn-rules"],
        "outbound": "vpn"
      }
    ],
    "final": "direct"
  }
}
```

Замените `configurer-host:8080` на адрес, где запущен конфигуратор.

**Формат rule-set:**
- `format: "source"` - правильный формат для JSON rule-set
- `update_interval: "1m"` - sing-box будет автоматически проверять обновления каждую минуту
- Версия rule-set автоматически увеличивается при применении правил

### Развертывание в Docker

Пример docker-compose.yml:

```yaml
version: '3'
services:
  configurer:
    image: debian:bookworm-slim
    restart: always
    command: /app/sing-box-configurer
    volumes:
      - ./sing-box-configurer:/app/sing-box-configurer:ro
      - ./config.json:/app/config.json:ro
      - ./rules.json:/app/rules.json:rw
    ports:
      - "8080:8080"
    working_dir: /app

  sing-box:
    image: ghcr.io/sagernet/sing-box
    network_mode: host
    volumes:
      - ./sing-box-config.json:/etc/sing-box/config.json
    depends_on:
      - configurer
```

Статические файлы встроены в бинарник `sing-box-configurer`, поэтому монтировать папку `web/` не требуется.

### Работа с интерфейсом

1. Откройте браузер и перейдите на `http://your-server:8080`

#### Вкладка "Правила"

2. Добавьте правила для маршрутизации через VPN:
   - **Домен** - точное совпадение домена (например, `example.com`)
   - **Суффикс домена** - все поддомены (например, `.google.com` или `google.com`)
   - **IP адрес** - конкретный IP (например, `8.8.8.8`)
   - **CIDR** - диапазон IP адресов (например, `192.168.1.0/24`)
3. После добавления правил нажмите **"Применить правила"** для сохранения изменений
4. Sing-box автоматически подхватит обновленный rule set

#### Вкладка "URL Источники"

1. **Добавление URL источника:**
   - Укажите URL файла со списком правил (один адрес на строку)
   - Установите интервал обновления в минутах (по умолчанию 60)
   - Добавьте описание для удобства
   - Нажмите **"Проверить"** для валидации URL перед добавлением
   - Нажмите **"Добавить"** для сохранения

2. **Формат файла по URL:**
   ```
   # Комментарии (строки начинающиеся с # или //)
   192.168.1.0/24
   10.0.0.1
   172.16.0.0/12
   
   # Пустые строки игнорируются
   8.8.8.8
   ```

3. **Применение URL источников:**
   - После добавления нажмите **"Применить URL источники"**
   - Источники начнут автоматически загружаться с указанным интервалом
   - Статус загрузки отображается в таблице (успех/ошибка)

4. **Просмотр загруженных правил:**
   - Нажмите кнопку **"Посмотреть"** напротив источника
   - Откроется модальное окно со списком всех загруженных правил

5. **Мониторинг:**
   - **Статус** - показывает успешность последней загрузки
   - **Обновлено** - время последнего обновления
   - **Элементов** - количество загруженных правил

### Статусы правил

- **Применено** (зеленый) - правило сохранено и доступно через API
- **Ожидает** (оранжевый) - правило добавлено, но еще не применено

Кнопка "Применить правила" показывает количество ожидающих правил и становится активной только при наличии неприменённых изменений.

## API

### Rules API

#### GET /api/rules
Получить список всех правил с информацией о статусе
```json
{
  "rules": [
    {
      "id": "uuid",
      "type": "domain",
      "value": "example.com",
      "description": "Example domain",
      "applied": true,
      "deleted": false,
      "created_at": "2026-06-02T20:00:00Z"
    }
  ],
  "pending_count": 0
}
```

#### POST /api/rules/add
Добавить новое правило
```json
{
  "type": "domain",
  "value": "example.com",
  "description": "Example domain"
}
```

#### POST /api/rules/delete
Удалить правило
```json
{
  "id": "uuid-правила"
}
```

#### POST /api/apply
Применить все ожидающие правила

#### GET /api/ruleset
Получить rule set в формате sing-box (используется sing-box для автоматического получения правил)
```json
{
  "version": 5,
  "rules": [
    {
      "domain": ["example.com"],
      "domain_suffix": ["google.com"],
      "ip_cidr": ["8.8.8.8/32", "192.168.1.0/24"]
    }
  ]
}
```

**Примечания:**
- `version` определяет версию формата правил, на которую ориентируется sing box
- Возвращаются только примененные правила (с `applied: true`)
- Включает правила из URL источников
- Если нет примененных правил, `rules` будет пустым массивом

### URL Sources API

#### GET /api/url-sources
Получить список всех URL источников
```json
{
  "url_sources": [
    {
      "id": "uuid",
      "url": "https://example.com/ips.txt",
      "description": "Example IP list",
      "interval": 60,
      "last_update": "2026-06-04T19:30:00Z",
      "last_status": "success",
      "last_error": "",
      "items_count": 150,
      "applied": true,
      "deleted": false,
      "created_at": "2026-06-04T19:00:00Z"
    }
  ]
}
```

#### POST /api/url-sources/add
Добавить новый URL источник
```json
{
  "url": "https://example.com/ips.txt",
  "description": "Example IP list",
  "interval": 60
}
```

#### POST /api/url-sources/delete
Удалить URL источник
```json
{
  "id": "uuid-источника"
}
```

#### POST /api/url-sources/apply
Применить все ожидающие URL источники (запускает периодическое обновление)

#### POST /api/url-sources/validate
Валидировать URL перед добавлением
```json
{
  "url": "https://example.com/ips.txt"
}
```

Ответ:
```json
{
  "valid": true,
  "error": "",
  "count": 150
}
```

#### GET /api/url-sources/rules?id=uuid
Получить список загруженных правил для конкретного URL источника
```json
{
  "cidrList": [
    "192.168.1.0/24",
    "10.0.0.1",
    "8.8.8.8"
  ],
  "domains": [
     "google.com",
     "ya.ru"
  ],
  "domainSuffixes": [
     "tg.me",
     "discord.com"
  ]
}
```

## Рабочий процесс

1. **Добавление правил** - правила сохраняются в `rules.json` со статусом `applied: false`
2. **Применение правил** - при нажатии "Применить правила":
   - Статус правил меняется на `applied: true`
   - Удаленные правила окончательно удаляются из `rules.json`
   - Правила становятся доступны через `/api/ruleset`
3. **Автоматическое обновление** - sing-box периодически запрашивает `/api/ruleset` и обновляет правила маршрутизации
